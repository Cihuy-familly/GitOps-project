Hop-by-hop detail

1
DNS Resolution

Browser lookup vote.cihuylabs.my.id → Cloudflare DNS balikin 2 IP anycast (104.21.49.237 dan 172.67.195.211).

Cloudflare
2
Cloudflare Edge

Request masuk ke Cloudflare Edge terdekat. Karena DNS di-proxied (orange cloud), Cloudflare gak langsung forward ke IP origin, tapi lewat Cloudflare Tunnel.

Cloudflare
3
cloudflared Pod

Di cluster K3s, cloudflared jalan dengan 2 replica. Dia koneksi keluar (outbound) ke Cloudflare Edge — jadi gak perlu buka port inbound di firewall. Dia forward request ke http://istio-ingress.istio-system:80.

K3s
4
Istio Ingress Gateway

Gateway baca Host: vote.cihuylabs.my.id header dan cocokin dengan sandbox-gateway (Gateway CRD) yang listen di port 80. Gateway ini selector-nya istio: ingressgateway.

K3s
5
VirtualService Routing

VirtualService quiz-vote (di namespace quiz-vote) cocokin host vote.cihuylabs.my.id dan route ke frontend.quiz-vote.svc.cluster.local:5000.

K3s
6
Service → Pod

K8s Service frontend (ClusterIP) forward ke pod yang punya label app: frontend. Istio sidecar (Envoy) di pod handle traffic sebelum sampai ke container Flask.

K3s
7
Internal API calls

Frontend Flask panggil vote-api:8000 (POST /vote, GET /quizzes) dan result-api:8001 (GET /results) — semua via service DNS, dalam namespace yang sama. vote-api pake Redis + Postgres, result-api langsung ke Postgres.

🧪 Flux Feature Testing

Semua test di bawah bisa dijalanin dari terminal kamu. Gunakan untuk verify bahwa Flux bekerja seperti yang diharapkan.

🔁 A. Basic Reconciliation

Test bahwa Flux bisa menarik perubahan dari Git dan menerapkannya ke cluster.

📋 Test Case: Edit deployment YAML → Flux deploy
StepCommandExpected Result
1 # Edit file di GitOps repo
nano result-api-deployment.yaml		 Ubah replica atau tag image
2 git commit -am "test" && git push Push ke remote
3 flux reconcile source git flux-system -n flux-system Flux tarik commit baru
4 kubectl get pods -n quiz-vote -w Pod restart dengan perubahan baru 
# Alternative: force reconcile both source + kustomization
flux reconcile kustomization flux-system -n flux-system

# Cek status reconciliation
flux get kustomizations -n flux-system

# Detail log Flux untuk quiz-vote
flux get kustomizations -n flux-system | grep quiz-vote

🔄 B. Drift Detection

Test bahwa Flux mengembalikan resource yang diedit manual ke keadaan di Git (desired state).

📋 Test Case: Edit pod manual → Flux revert
StepCommandExpected Result
1 kubectl edit deployment -n quiz-vote frontend Ubah replica jadi 3
2 kubectl get deploy -n quiz-vote frontend DESIRED=3, CURRENT=3
3 flux reconcile kustomization flux-system -n flux-system —
4 kubectl get deploy -n quiz-vote frontend DESIRED=1 (balik ke Git state)

Kenapa ini penting: Kalau someone (atau automation lain) ubah resource di cluster langsung, Flux akan revert dalam beberapa menit. Ini yang dimaksud declarative reconciliation — cluster harus cocok dengan Git.

Cek riwayat reconciliation Flux:

# Lihat event terakhir
kubectl describe kustomization -n flux-system flux-system

# Cek log kustomize-controller
kubectl logs -n flux-system deploy/kustomize-controller --tail=50

⏸️ C. Suspend & Resume

Test bahwa Flux bisa dihentikan sementara (misal untuk maintenance atau debugging manual).

# Suspend — Flux berhenti reconcile kustomization ini
flux suspend kustomization flux-system -n flux-system

# Edit sesuatu di cluster (misal ubah replica)
kubectl scale deployment -n quiz-vote frontend --replicas=3

# Verify — perubahan TETAP, gak direvert Flux
kubectl get deploy -n quiz-vote frontend
# → DESIRED=3 (karena Flux sedang suspend)

# Resume — Flux lanjut reconcile lagi
flux resume kustomization flux-system -n flux-system

# Verify — Flux revert balik ke 1
kubectl get deploy -n quiz-vote frontend
# → DESIRED=1
💡 Kapan pakai suspend?
  • Emergency fix langsung di cluster (gak sempat push ke Git)
  • Debugging yang perlu cluster diverifikasi dulu
  • Maintenance window

⚠️ Image Automation = Auto-commit ke Git

Flux bakal nulis tag baru langsung ke file YAML di repositori Git sebagai bot TeflonCD. Jadi setiap ada tag image baru, Flux commit + push ke repo → trigger reconciliation lagi.

Setup ini gak diwajibkan sekarang — untuk development, update manual tag juga cukup.

❤️ E. Health Check & Readiness

Test bahwa probe (liveness + readiness) jalan dengan benar dan Flux cuma deploy pods yang sehat.

# Cek status pod — semua harus 2/2 READY
kubectl get pods -n quiz-vote

# Cek endpoint service — harus ada IP
kubectl get endpoints -n quiz-vote frontend

# Test health endpoint langsung
kubectl exec -n quiz-vote deploy/frontend -c frontend -- \
  python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:5000/health').read())"

# Simulasi failure: matiin health endpoint (kalau ada env ERROR_RATE)
# Set ERROR_RATE=1.0 via ConfigMap → semua request 500 → readiness probe gagal

Cara test probe failure tanpa merusak app: set ERROR_RATE=1.0 dan ARTIFICIAL_DELAY_MS=30000 via ConfigMap. Pod akan gagal readiness probe dalam beberapa detik, Istio akan remove dari upstream, dan kamu akan lihat "no healthy upstream" lagi — tapi kali ini sengaja.

# Set error rate tinggi
kubectl patch configmap -n quiz-vote quiz-vote-config -p '{"data":{"ERROR_RATE":"1.0"}}'

# Tunggu 10-15 detik, cek pod
kubectl get pods -n quiz-vote -w
# → frontend akan jadi 1/2 (sidecar aja yang jalan)

# Balikin normal
kubectl patch configmap -n quiz-vote quiz-vote-config -p '{"data":{"ERROR_RATE":"0.0"}}'

Notifikasi yang dikirim Flux ke Discord:

📨 Event types yang trigger notif
  • ✅ Kustomization ready — reconcile sukses
  • ❌ Kustomization failed — reconcile error
  • ✅ HelmRelease ready — upgrade sukses
  • ❌ HelmRelease failed — upgrade error
  • 🔄 Git artifact updated — Flux tarik source baru
